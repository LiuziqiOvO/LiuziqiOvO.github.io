很多技术笔记的问题不是写得太少，而是写得不能复用。收藏了链接，贴了命令，复制了报错，记录了某个结论。过一段时间回头看，只能想起“当时解决过”，却很难再用这些材料解决下一个问题。

笔记如果只是保存信息，它的价值会很快衰减。真正有复用价值的技术笔记，应该保存上下文、判断依据和适用边界。它不是一个收藏夹，而是一份未来可以调用的工程资产。

## 信息本身不稀缺，稀缺的是判断路径

命令、API、配置项、参数含义，大多数都能重新搜索到。搜索不到的通常是当时为什么这样选、踩过哪些坑、哪些方案被排除、结论依赖什么环境。

例如一条命令：

```bash
perf record -g --call-graph=dwarf ./app
```

这当然有用，但它只回答“怎么做”。更有价值的是补上：

- 为什么这里要用 `dwarf` 而不是 frame pointer。
- 这个程序是否保留了调试符号。
- 采样开销是否影响被测程序。
- 当时想定位 CPU 热点，还是想看调用链。
- 这个方法在哪些语言运行时下不稳定。

这些信息很难从命令本身恢复。笔记要保存的，正是这种判断路径。

## 好笔记要写清楚触发场景

脱离场景的结论容易误导。一个配置在某个项目里有效，不代表它是通用最佳实践。一个优化在小数据集上明显，在大数据集上可能无效。一个排障方法在本地环境好用，在线上容器环境里可能拿不到同样的信息。

所以笔记开头最好先写触发场景：

```text
我在什么环境下遇到这个问题？
问题出现前我想达成什么目标？
当时有哪些约束？
哪些信息是确定的，哪些只是猜测？
```

这几句话看起来朴素，但能决定笔记未来是否可用。没有场景，读者只能拿结论硬套。保留场景，读者才能判断它和当前问题是否同类。

## 过程比结论更能复用

很多笔记只写最后答案：把某个参数改成多少，重启哪个服务，安装哪个依赖。这样的笔记短期有效，长期价值有限。因为下一次问题通常不会一模一样。

过程型笔记更耐用。它记录如何从现象走到结论：

- 先观察了哪些指标。
- 排除了哪些方向。
- 哪个证据让判断发生转向。
- 最终修改为什么能解释现象。
- 还有哪些遗留不确定性。

这样的笔记即使结论过期，方法也还能复用。工具会变，版本会变，系统会变，但从现象到证据再到判断的路径更稳定。

## 适用边界要主动写出来

技术写作里最容易缺失的是边界。很多结论看起来坚定，只是因为省略了前提。

例如：

```text
把 iodepth 调大可以提升吞吐。
```

这句话可能对，也可能错。更好的写法是：

```text
在底层设备有足够并行能力、请求可并发提交、应用能承受更高排队延迟的前提下，提高 iodepth 可能提升吞吐；但它也会拉高尾延迟，尤其不适合只看单请求响应时间的场景。
```

这不是啰嗦，而是让结论变得可审查。工程判断经常不是“对或错”，而是“在什么条件下值得采用”。

适用边界至少可以从几类角度写：

- 环境边界：内核版本、硬件、文件系统、运行时。
- 负载边界：数据规模、并发、读写比例、冷热分布。
- 目标边界：追求吞吐、延迟、稳定性还是可维护性。
- 风险边界：副作用、不可逆操作、观测盲区。

边界写得越清楚，未来误用的概率越低。

## 索引比分类更重要

分类通常是树状的：Linux、Git、性能分析、存储系统。它有用，但不够。真实问题往往横跨分类：一个延迟问题可能同时涉及 Linux 调度、存储 I/O、日志系统、压测方法和应用线程池。

所以笔记系统还需要索引。索引不是简单标签堆砌，而是围绕问题建立入口：

- 如何定位 P99 抖动？
- 如何判断 benchmark 是否可信？
- 如何排查磁盘 I/O 等待？
- 如何比较两个方案的工程风险？
- 如何记录一次线上问题？

这种问题型索引更接近未来检索方式。因为人遇到问题时，很少会想“我要查操作系统分类”，更常想“为什么这个请求偶尔很慢”。

## 把笔记写成给未来自己的接口

写笔记时可以把未来的自己当成调用方。未来的自己不会记得当时的上下文，也不会天然相信现在的结论。他需要的是一个清晰接口：

```text
输入：遇到什么问题时可以看这篇。
输出：看完能做什么判断或动作。
前提：这篇依赖哪些环境和假设。
限制：哪些地方不能直接照搬。
```

这个接口越稳定，笔记越像资产。否则它只是一次性的情绪缓存：当时写下来觉得很安心，后来再也用不上。

## 写少一点，但写到能复用

技术笔记不需要追求覆盖所有细节。很多时候，写得太满反而会淹没重点。更好的目标是信息密度高：保留那些未来无法轻易搜索、无法从命令本身推导、无法从官方文档直接获得的内容。

一篇有价值的笔记，至少应该回答：

- 这个问题为什么值得记？
- 当时的关键上下文是什么？
- 结论是怎么来的？
- 它适用于哪些情况？
- 下次遇到类似问题应该先看什么？

如果能回答这些问题，哪怕篇幅不长，也比十页复制粘贴更有价值。

技术积累不是材料越多越好，而是材料能不能被重新激活。笔记的目标不是证明自己学过，而是让未来的判断更快、更稳、更少重复走弯路。
